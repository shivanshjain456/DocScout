### S4. Diagnosis of the V8 failure — a security control silently disabled

V8 requires .claude/hooks/dangerous-bash.sh to be EXECUTABLE. The hook logic was
intact (deny 'rm -rf /' -> exit 2, allow 'uv run pytest -q' -> exit 0); only the
file mode was wrong.

Root cause: the workspace snapshot stripped the executable bit from every shebang
script in the repository, and commit c2eeb90 recorded all 16 of them as 100644.
A file-mode change is invisible when reading a diff, so it was committed unnoticed.

Consequence, stated plainly: .claude/hooks/dangerous-bash.sh is the agent command
denylist (SECURITY.md S-16). A non-executable hook does not run. The control that
blocks destructive commands was disabled by an invisible metadata loss - a control
that still *looked* present in every listing of the repository.

Scope: 16 files, including all three .claude/hooks/, scripts/verify_setup.sh,
infra/initdb/02-app-role.sh, both scripts/*.py and six vendored Superpowers helpers.
(The initdb script still worked, because Postgres SOURCES a non-executable *.sh
instead of running it - so the app role exists. Luck, not design.)

Fix: chmod +x on all 16, recorded by git as mode 100644 => 100755.

Guard: added pre-commit hook `check-shebang-scripts-are-executable`, so a shebang
script without the exec bit can no longer be committed. Proven to fire:

  $ chmod -x .claude/hooks/dangerous-bash.sh && pre-commit run check-shebang-scripts-are-executable --all-files
    .claude/hooks/dangerous-bash.sh: has a shebang but is not marked executable!
  $ chmod +x .claude/hooks/dangerous-bash.sh && pre-commit run ... --all-files
    check that scripts with shebangs are executable..........................Passed
