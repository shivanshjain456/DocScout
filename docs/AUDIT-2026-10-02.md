### Material disagreements, and how they were resolved

* **S1/S3/S7 say "faithfulness, RAGAS ≥ 0.9" is table stakes; this project publishes no
  faithfulness number.** Not a gap to fix by adding one. The system has no generator
  (ADR-0008), so the metric has no subject, and U-1 closed as a formal withdrawal with
  enforcement (`tests/test_rescope.py`). Inventing the number is the failure mode S3
  explicitly warns about. Recorded as a *scope* decision, not a deficiency.
* **S7/S8 disagree in emphasis on OTel GenAI readiness.** S7 presents the conventions as
  implementable today; S8 shows nothing GenAI-specific is Stable and the repo moved in
  June 2026. Resolution: adopt the **Stable** core conventions plus the `retrieval` span
  shape, pin the convention version in config, and document the instability — rather than
  claim "OpenTelemetry compliant".
* **S4 asserts "80%+ coverage"; S1/S6 never mention coverage.** Treated as engineering
  judgement, not a hard expectation: coverage is listed below as *measure and publish*,
  not *hit a number*.
* **Several sources recommend Langfuse/Phoenix specifically.** Rejected as vendor-specific;
  an OTLP exporter satisfies the same signal without a hosted dependency this project
  cannot provision.

## 3. Prioritised gap checklist

Classification: **DEFECT** = wrong behaviour today · **ABSENT** = capability missing ·
**INCOMPLETE** = partially built · **QUALITY** = works but weak · **OPTIONAL** = enhancement.

Priority: **P0** = materially damages the hiring signal or correctness · **P1** = expected
by most reviewers · **P2** = differentiator · **P3** = nice to have.

---

### P0

**G1 — Invisible / private-use characters survive ingestion into embeddings and citations** · DEFECT
* *Expectation (S10, OWASP LLM09):* extraction must strip formatting and detect hidden content so it "doesn't survive ingestion"; validate documents before they enter the knowledge base.
* *Current state:* a character-level scan of all 170 stored chunks found **4 occurrences of U+F0E0** (Unicode Private Use Area — a Wingdings breadcrumb arrow in SEBI circulars: `under the link "Legal ␀ Circulars"`). They are embedded into vectors, tokenised, returned in API responses, and **2 of the 4 chunks are cited by the gold set**. `app/ingest/clean.py` blanks Devanagari, Latin Extended-B, spacing modifiers and U+FFFD, but no Cf (format), Co (private-use) or Cs (surrogate) category, and no zero-width or bidirectional-override characters.
* *Gap:* no Unicode-category-based sanitisation; no detection or reporting of hidden content.
* *Hiring-signal impact:* a reviewer who greps the corpus finds garbage in served citations. It is also the single most RAG-specific item in the OWASP list, so it is the cheapest credible answer to "how did you handle indirect prompt injection?"
* *Dependencies:* none.
* *Acceptance criteria:* every Cf/Co/Cs codepoint and every zero-width/bidi control is blanked **length-preservingly**, so `char_start`/`char_end`, content-derived `chunk_id`s and all 150 pinned gold citations are unchanged; a re-ingest reports how many were removed and from which documents; the eval gate passes; FR-7 re-derivation still holds for 170/170 chunks.
* *Verification:* re-run the character scan → 0 findings; `make ingest && python -m app.ingest verify`; `make eval-gate`; diff chunk IDs before/after.

**G2 — No logging configuration anywhere; `structlog` declared but unused** · ABSENT
* *Expectation (S4 red-flag table, S5, S6):* "missing logs" is an explicit red flag; observability "from day one".
* *Current state:* `grep -rn 'basicConfig|dictConfig|JSONFormatter' app/ scripts/` → **no matches**. Only `app/api/app.py` calls `logger.*` (6 sites), against an unconfigured root logger, so records are emitted at WARNING by uvicorn's handler and the `logger.info` access lines are silently discarded. `structlog` is a declared dependency and imported nowhere.
* *Gap:* no structured output, no level control, no correlation between records.
* *Hiring-signal impact:* high and cheap. "Can you debug this from logs?" currently answers itself.
* *Dependencies:* none. Foundation for G3/G4/G5.
* *Acceptance criteria:* one logging setup module; JSON lines in production, human-readable when a TTY; level from env; every API request logs method, path, status, duration, key fingerprint and request id; secrets and API keys never appear; ingestion logs per-stage counts.
* *Verification:* start the API, issue requests, assert each line parses as JSON and contains the required fields; a test asserts the configured key never appears in emitted records.

**G3 — No request correlation id on successful responses** · INCOMPLETE
* *Expectation (S4, S5):* trace a request end to end.
* *Current state:* `app/api/app.py` mints a correlation id **only** in the 500 handler; successful responses carry no identifier and no `X-Request-ID` header is read or emitted.
* *Gap:* a caller reporting "this query was wrong" cannot be joined to a log line.
* *Dependencies:* G2.
* *Acceptance criteria:* accept an inbound `X-Request-ID` (validated, length-capped) or mint one; echo it on every response including errors; include it in every log record for that request.
* *Verification:* curl with and without the header; assert echo and log join in tests.

### P1

**G4 — No metrics endpoint** · ABSENT
* *Expectation (S1 "observability + cost tracking", S4 "metrics dashboards").*
* *Current state:* no `/metrics`; no counters. `/healthz` exposes cache hit/miss only.
* *Acceptance criteria:* RED metrics (request count by route/status, latency histogram, in-flight), plus retrieval-specific counters (cache hits, arm latencies, rate-limit rejections) in Prometheus text format; endpoint documented and unauthenticated-but-safe (no query text).
* *Verification:* scrape `/metrics`, assert well-formed exposition and that counters move under load.
* *Dependencies:* G2.

**G5 — No distributed tracing / OTel instrumentation** · ABSENT
* *Expectation (S5, S7, S8); note S8: the GenAI conventions are **Development**, not Stable.*
* *Current state:* `opentelemetry` appears nowhere in `app/` or `pyproject.toml`.
* *Acceptance criteria:* optional OTLP exporter, off unless configured; a `retrieval` span per query following `gen_ai.operation.name=retrieval`; query text **not** captured by default (S7: Opt-In, PII); pinned convention version and a documented note that the GenAI surface is unstable.
* *Verification:* run with a local collector or console exporter; assert span name/attributes; assert query text absent unless explicitly enabled.
* *Dependencies:* G2.

**G6 — No Dockerfile for the service** · ABSENT
* *Expectation (S4 explicitly lists Dockerfiles; S5 "Docker, CI/CD").*
* *Current state:* `docker-compose.yml` defines only Postgres and Redis. There is no image for the API, so "deploy this" has no answer.
* *Acceptance criteria:* multi-stage, non-root, pinned base digest, `uv sync --frozen`, healthcheck, model cache handled explicitly (the 130 MB encoder must not be downloaded at container start without a documented volume); image builds and serves `/healthz`.
* *Verification:* `docker build` then run and curl — **blocked here: no Docker daemon in this sandbox**; must be verified where one exists.

**G7 — `docker-compose.yml` contradicts reality and the README** · DEFECT
* *Current state:* it pins `pgvector/pgvector:0.8.2-pg18`, but every published number was measured on **0.8.6** (`dev_db_native.sh`, CI job, SETUP_REPORT). It also starts a Redis container that no code uses. README line 176 says "There is no `docker compose up`" while the file is tracked at the repo root.
* *Hiring-signal impact:* a reviewer who runs the documented-as-nonexistent file gets a different extension version than the baselines — the exact reproducibility failure this project otherwise defends well.
* *Acceptance criteria:* one story. Either align the pin to 0.8.6 and document compose as a supported path, or delete the file and the Redis service. Not both.
* *Verification:* `grep` the pin against `dev_db_native.sh` and `ci.yml` in a test.

**G8 — Dependency surface: 9 declared, unimported packages** · QUALITY (OWASP LLM04 supply chain)
* *Current state:* `openai`, `anthropic`, `ragas`, `deepeval`, `langchain-community`, `rank-bm25`, `respx`, `jinja2`, `structlog` are declared in `pyproject.toml` and imported nowhere in `app/`. `rank-bm25` is notable: BM25 is hand-implemented in `app/retrieval/lexical.py`.
* *Acceptance criteria:* each dependency either used, moved to a dev/optional extra, or removed, with the reason recorded; lockfile regenerated; suite green.
* *Verification:* an automated check that every runtime dependency is imported somewhere under `app/`.

**G9 — No automated dependency vulnerability scan** · ABSENT (OWASP LLM04)
* *Current state:* CI runs ruff, mypy, pytest and gitleaks. No `pip-audit`/OSV step; no SBOM.
* *Acceptance criteria:* CI step failing on known-vulnerable pinned versions, with a documented triage path; SBOM artifact published per build.
* *Verification:* run the scanner locally and in CI; assert non-zero exit on a seeded vulnerable pin.

**G10 — Test coverage never measured** · QUALITY
* *Current state:* `pytest-cov` is a declared dependency; no `--cov` configuration, no coverage number published, no CI threshold.
* *Acceptance criteria:* coverage measured over `app/`, reported in CI, published in the README with the command, and a floor that fails the build. Branch coverage, not just line.
* *Verification:* `pytest --cov=app --cov-branch --cov-fail-under=N`.

**G11 — Unanswerable gold items are excluded from every metric** · INCOMPLETE
* *Current state:* 22 of 153 gold items (14.4 %) are unanswerable; `app/evals/runner.py` excludes them (`items_excluded_unanswerable`) and nothing scores abstention. The retrieval API has no confidence signal, so a question the corpus cannot answer returns ten confident-looking passages.
* *Expectation (S3 failure taxonomy; Q-18 requires refusal scored as PASS).*
* *Acceptance criteria:* a calibrated score threshold or margin rule; abstention precision/recall reported over the 22 unanswerable plus 131 answerable items; the API returns an explicit low-confidence signal rather than silently ranking.
* *Verification:* new metrics in `results.json`; threshold chosen on evidence, with the sweep committed.

**G12 — No retrieval audit log** · ABSENT (OWASP LLM09: "audit retrieval logs for suspicious patterns")
* *Current state:* queries are logged only to stdout via an unconfigured logger and are not persisted; there is no record of what was retrieved for whom.
* *Acceptance criteria:* durable, append-only record of (timestamp, key fingerprint, query hash, mode, returned chunk ids, latency); documented retention; query text hashed not stored by default.
* *Dependencies:* G2.

**G13 — No ingestion-time secret/PII scan of corpus content** · ABSENT (OWASP LLM02)
* *Current state:* gitleaks scans **source code**; nothing scans the ingested regulatory text, which is fetched from the public internet and stored verbatim.
* *Acceptance criteria:* ingestion flags candidate secrets/PII patterns in extracted text, records findings in the run report, and fails or quarantines per policy.

### P2

**G14 — No published architecture diagram image** · QUALITY — ASCII only in `ARCHITECTURE.md`; S1/S3 both call out a diagram in the 90-second scan. Needs a rendered SVG (inline, no external assets) in the README.

**G15 — No live public URL** · ABSENT — S1 ranks this third ("reviewers won't clone — they click"). **Blocked:** no cloud resources are provisioned by this project and no deploy credentials exist. Legitimate supporting work: the Dockerfile (G6) and a documented one-command deploy path.

**G16 — No demo video or GIF** · ABSENT — S1/S6. Cannot be produced in this environment (no screen capture). Supporting work: a scripted, reproducible terminal transcript.

**G17 — No CI badge** · ABSENT — the workflow has never run; there is no remote. Honest today; resolves only with a remote.

**G18 — Query text is not Unicode-normalised** · QUALITY — `SearchRequest.query` strips whitespace but applies no NFKC normalisation, so visually identical queries with different codepoints produce different cache keys and different BM25 lexemes. Same root cause as G1, on the query side.

**G19 — No load/concurrency profile** · INCOMPLETE — `bench_api.py` measures to concurrency 4 on 2 vCPU; U-14 remains half-open. Needs a documented saturation curve and the throughput knee, not a bigger number.

**G20 — Embedding cache does not survive a restart** · QUALITY — `app/api/cache.py` is in-process; every restart re-pays encode cost for repeat queries. `REDIS_URL` is configured and unused.

**G21 — No pagination or result-offset on `/v1/search`** · ABSENT — `k ≤ 20` with no cursor, so a caller cannot page deeper.

**G22 — No API versioning or deprecation policy** · QUALITY — the path is `/v1/` but nothing documents what v1 guarantees or how a breaking change would ship.

**G23 — Document supersession is modelled but never exercised** · INCOMPLETE — `is_current` and a one-current-per-document partial unique index exist in migration 0001; no ingest path ever supersedes a version, and no test covers a document being replaced by a newer revision. For a regulatory corpus where circulars are amended and withdrawn, this is the domain's central data-modelling question (U-12).

**G24 — No backup/restore or disaster-recovery procedure** · ABSENT — no documented `pg_dump`/restore path or tested recovery, despite the DB holding the only copy of embeddings (~20 min to rebuild).

**G25 — Graceful shutdown is unverified** · QUALITY — the lifespan closes the pool, but nothing tests that in-flight requests complete on SIGTERM.
